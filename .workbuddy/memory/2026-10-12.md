
## 响应式看板列宽 + Sidebar 自动折叠 (22:41)

Commander 截图：项目看板 4 列 phase 卡片（规划中/队列/进行中/AI?）最后一个被窗口右边切掉。

### 根因
- KanbanBoard `flex flex-1 gap-4 overflow-x-auto p-6` + 4 列 × 固定 `DEFAULT_COLUMN_WIDTH = 320px`，子元素 `flexShrink: 0`，小窗口下 4 列总宽超出容器但 `overflow-x-auto` 滚动条不可见/没出现
- Sidebar 宽度硬编码：展开 `w-64` (256px) / 折叠 `w-16` (64px)，不响应窗口宽度

### 改动
1. **`apps/desktop/src/renderer/stores/kanban-settings-store.ts`**：
   - 抽 `computeAutoColumnWidth(containerWidth, options)` 纯函数（默认 paddingPx=48 / gapPx=16 / min=MIN_COLUMN_WIDTH / max=MAX_COLUMN_WIDTH），clamp 到 [MIN, MAX]
   - width ≤ 0 → 返回 DEFAULT_COLUMN_WIDTH（容器未测量）
2. **`apps/desktop/src/renderer/components/KanbanBoard.tsx`**：
   - 新增 `kanbanContainerRef` + `useState` 容器宽度 + `ResizeObserver` 监听
   - `autoColumnWidth = useMemo(() => computeAutoColumnWidth(width, {columnCount: TASK_STATUS_COLUMNS.length}), [width])`
   - DroppableColumn `columnWidth` 改为 `columnPreferences?.[status]?.width ?? autoColumnWidth` —— 用户拖拽的 resize 偏好仍被尊重，未设置时按窗口宽度自适应
3. **`apps/desktop/src/renderer/components/Sidebar.tsx`**：
   - mount-time `useEffect`：window.innerWidth < 1024px 且 `!isCollapsed` 时自动 `saveSettings({ sidebarCollapsed: true })`
   - 只在 mount 跑一次，避免和用户的 manual toggle 打架；下次启动再判断
4. **新增测试** `src/renderer/stores/__tests__/kanban-settings-store.test.ts`（8 个）：覆盖 width=0/-1 fallback、平均分、MIN clamp、MAX clamp、自定义 padding/gap、columnCount=0/-2 边界

## 修复看板锁按钮无响应 (23:11)

Commander 截图：kanban 视图 6 个 phase 列，每列右上角有锁/设置按钮，红框标注。报告"点击了没有任何反应"。

### 根因（两个相关 bug 叠加）
1. **KanbanBoard 的 `projectId` 来源是 `tasks[0]?.projectId`** —— 当看板列空时（截图就是）`tasks[0]` = undefined → `projectId` = undefined → `loadKanbanPreferences` useEffect **不跑**（`if (projectId)` 守卫）→ `columnPreferences` 永远是 null
2. **toggleColumnLocked store action 有 `if (!state.columnPreferences) return state` 早返回守卫** —— 即便用户点按钮（即使 load 后来跑完了），在 null 状态下点也无响应。toggleColumnCollapsed / setColumnWidth 同样守卫

### 修复
1. **KanbanBoard 改用 `selectedProjectId`**（来自 useProjectStore），fallback 到 `tasks[0]?.projectId`。这样 user 进入看板时（即使 project 刚创建没任务）也能拿到 projectId → load 跑 → columnPreferences 初始化
2. **`toggleColumnLocked` 在 null 时 auto-init** —— 用 `state.columnPreferences ?? createDefaultPreferences()` 兜底，确保 click 永远生效。其他 mutator 保持早返回（根因被 KanbanBoard fix 覆盖）
