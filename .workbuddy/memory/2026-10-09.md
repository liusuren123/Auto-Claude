## 项目概览调研

Commander 要求了解 Aperant（前身 Auto Claude）项目的内部结构与架构。

**项目性质**：自主多智能体编码框架的桌面端 Electron 应用，主代码在 `apps/desktop/`（TypeScript + Vercel AI SDK v6），配套一个轻量 Python sidecar 处理 Graphiti 知识图谱记忆系统。

**关键架构结论**：
- AI 层完全在 `apps/desktop/src/main/ai/`，使用 Vercel AI SDK v6 的 `streamText()` + `stopWhen: stepCountIs(N)` 实现 agentic tool-use 循环
- 构建流水线走 `planning → coding → qa_review → qa_fixing → complete/failed`，由 `orchestration/build-orchestrator.ts` 驱动
- Agent 在 `worker_threads` 中执行，避免阻塞 Electron 主进程（`agent/worker.ts` + `agent/worker-bridge.ts`）
- 多 Provider 通过 `createProviderRegistry()` 统一抽象（Anthropic/OpenAI/Google/Bedrock/Azure/Mistral/Groq/xAI/Ollama）
- 9 个内置工具 + 多个 MCP 工具（auto-claude/Context7/Linear/Graphiti/Puppeteer/Electron）
- 安全模型（`security/`）：bash validator、命令解析器、路径限制、密钥扫描、命令动态允许列表
- 工作流：用户在 git worktree 中独立工作，主分支保持干净；最后 AI 辅助语义合并

**主要待深入的方向**（用户尚未要求，仅记录）：
- `apps/desktop/src/main/ai/orchestration/` 的 phase 转换细节
- `apps/desktop/src/main/agent/` 的 worker bridge 通信模式
- `apps/desktop/src/main/terminal/` 的 PTY 守护进程
- `apps/desktop/src/main/claude-profile/` 的多账号/限流检测

## Bug 修复：terminal-session-store 冗余全量写盘

**现象**：升级后全量测试仅 1 个失败 —— `terminal-session-store.test.ts > should prevent timer accumulation on rapid deletes`，`Test timed out in 5000ms`（实测 6775ms）。单独重跑稳定复现，非 flaky。

**根因**（`src/main/terminal-session-store.ts` 的 `removeSession`）：
无条件调用 `this.save()`，即便 `filter` 什么都没删。测试循环 100 次删除同一 session，第 1 次就删掉了，后 99 次数组长度不变却仍各触发一次全量持久化。而 `save()` 是**同步原子写**（`JSON.stringify` → `writeFileSync(temp)` → rename 轮转 backup/current），单次 2-3 次磁盘 IO，Windows 上叠加起来直接吃掉 5s 预算。

**修复**（最小改动）：只在 `filter` 前后数组长度真的变化时 `save()`。
```ts
const beforeCount = todaySessions[projectPath].length;
todaySessions[projectPath] = todaySessions[projectPath].filter(s => s.id !== sessionId);
if (todaySessions[projectPath].length !== beforeCount) {
  this.save();
}
```
效果：6775ms → 1025ms（与同文件其他用例 ~900ms 持平），该文件 28/28 通过。

**归属判定（重要）**：该源码与测试均出自 `75869f7e feat: migrate from Python Claude Agent SDK to Vercel AI SDK v6 (#1891)`，属**既有缺陷**，并非本次 v7 升级引入。用 `git log -- <file>` 确认归属是区分"升级引入"与"既有 bug"的可靠手段，别只看表面现象就归因。

### ⚠️ system: → instructions: 必须按文件清单精确替换（21 文件）

- `src/main/platform/index.ts`、`platform/types.ts` — 平台信息 `system: [...]`

- `codex-oauth.ts` — CSS 的 `system-ui`，无关
